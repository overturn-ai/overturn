# Overturn Capture for Gorgias

This package ships a **Chromium extension** that inserts a panel into the Gorgias ticket sidebar. Gorgias's documented HTTP sidebar widgets render API data; they do not expose the unsent reply composer or a pre-send hook. This extension runs as a content script instead of claiming that a native HTTP widget can observe/send drafts. The ZIP is for **Load unpacked** (unzip `dist/overturn-gorgias-app.zip` then load `dist/app` in `chrome://extensions`), **not** a Gorgias Developer Portal app upload.

Set the Overturn API key under extension **Options**, then reload a Gorgias ticket. Credentials remain in extension storage and the background service worker; the content script only sends the capture payload to the worker. The extension requests access to `https://*.gorgias.com/*` and `https://api.overturn.run/*`. Self-hosted Overturn needs its HTTPS origin added to `host_permissions` before rebuilding. Do not ship a custom API URL without restricting/validating its host in production.

The content script watches the active reply editor. A one-step jump of at least 80 characters (configurable) from a near-empty editor, or a preloaded reply, is treated as a draft; it can also be marked manually. On a send click or Ctrl/Cmd+Enter it snapshots the visible ticket messages, subject, customer email and order fields (when exposed by `data-testid="order-*"`), and sends the capture asynchronously. `require_reason` means a changed reply without a reason **is not captured**; the native send is **never intercepted or blocked**. No other ticket is read before a draft exists. If a send succeeds without capture, the panel warns the agent.

Gorgias has no documented public composer/sidebar DOM contract. The selectors in `src/main.ts` (`data-testid`/`aria-label` for editor, send button, messages, sidebar and order fields) need verification against a real Gorgias account; if selectors differ, update them before deployment. Keyboard send shortcuts other than Ctrl/Cmd+Enter and UI variants not matching those selectors are not captured. The DOM snapshot is limited to rendered messages, not necessarily the entire paginated ticket history. An SDK/webhook-based native widget would require a server-side integration to obtain the post-send message, but cannot recover an unsent draft without an additional composer bridge.

Build: `pnpm --filter @overturn-ai/gorgias-app build`. Test/typecheck: `pnpm --filter @overturn-ai/gorgias-app test` and `pnpm --filter @overturn-ai/gorgias-app typecheck`.
