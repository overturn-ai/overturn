# Overturn for Front

A Front sidebar plugin that watches the selected conversation for a saved draft and a newly sent outbound message, then posts the draft/sent pair to `POST /v1/capture`.

## Build

Requires Node.js 22+, pnpm 10+, and the repository workspace dependencies. The new Front SDK dependency is `@frontapp/plugin-sdk` v1.x; run `pnpm install` after adding this package so the workspace lockfile resolves it.

```bash
pnpm install
pnpm --filter @overturn-ai/front-plugin test
pnpm --filter @overturn-ai/front-plugin typecheck
pnpm --filter @overturn-ai/front-plugin build
```

The build writes the hosted static app to `dist/app/` and, when the system `zip` utility
is available, packages it as `dist/overturn-front-plugin.zip`. Front sidebar plugins are
hosted web apps: configure the plugin's Side panel URL to the deployed `app/index.html`;
the ZIP is a convenient build artifact, not an uploadable Front Marketplace package.

## Front setup

1. Create a Front developer app in **Settings → Company → Developers**.
2. Add a **Sidebar Plugin** feature and point its URL to the hosted `app/index.html` (or your local development server).
3. Install/pin the plugin in the Front workspace.
4. Open a conversation and enter an Overturn project API key in the plugin.

The key is held in `sessionStorage` for the current plugin tab. For a production release, use a server-side credential broker or an approved Front secure configuration mechanism rather than sharing a project key across teammates.

## Capture behavior

The plugin polls the active single-conversation context for its `draftId`, fetches the draft through the Front Plugin SDK, and watches the message list for a new outbound message. It then builds a `source: "front"` payload with `externalId: "fr:<conversation id>"`, prior conversation context (excluding the sent reply), draft and sent text, teammate identity, and reason. Context is limited to messages available through the current Plugin SDK context; Front notes that some messages may not be loaded for the user. Unsent captures remain queued across conversation changes; failed API posts can be retried from the plugin.

`reason_pack` supports `claims` and `support`. A changed reply with `require_reason` enabled is held in the plugin's capture queue until a reason code is selected. Capture errors are caught and never interrupt Front's send workflow.

## Attribution and SDK limitations / acceptance notes

The Front Plugin SDK exposes a saved draft ID and draft content, but does not expose reliable metadata identifying whether a draft was generated by AI or written by a human. This implementation labels the draft as `draft:observed` and records `draftOrigin: "unverified"`; it must not be represented as verified AI output without an agreed marker or workflow.

The Front Plugin SDK documents context updates, `fetchDraft`, and `listMessages`, but
does not document a pre-send interception or send-cancellation hook for sidebar plugins.
Therefore this implementation cannot truly block Front's Send action while a reason is
missing. With `require_reason` enabled, it queues the changed draft/sent pair and waits
for the agent to select a reason before posting the capture; the message itself has
already been sent by Front. Capture network errors are caught and do not interrupt
Front's send workflow.

These are known acceptance gaps against a literal interpretation of “AI draft” and “changed reply blocked until reason”. They require confirmation from the bounty maintainers or a Front-supported interception surface / agreed attribution workflow before claiming full compliance.
