Capture where the reviewer works

Wrap the model client you already have and every prompt, tool call and answer is recorded. Your own review UI files the fix with <CorrectButton> or ov.correct(); anything else posts the same thing to /v1/capture.

2

Or record the agent itself

Wrap the OpenAI, Anthropic or Vercel AI SDK client you already have, or point an OpenTelemetry exporter at /v1/traces; then approve, edit or reject in Slack, with <CorrectButton>, or from code. Either way the case freezes the original, the fix and the reason.

3

Replay before you ship

Replay the whole log against any model or prompt before you ship; the report leads with the old fixes that broke. The same command runs in the GitHub Action and fails the pull request on a regression.

From an agent's fix to a test that runs before every change.

Record

The Zendesk app records the AI draft and the thread the agent saw; or wrap the model client you already have and every prompt, tool call and answer is recorded with a fingerprint.

Correct

The agent sends the reply as drafted, or changes it and picks a reason in one click, in the help desk they already use. The case freezes with the AI's draft, the agent's fix, and the reason.

Replay

Run every case against a new model or prompt from the CLI, the app, or CI. Tools are answered from the recording; nothing fires twice.

Report, and gate the change

Regressions first, with the baseline beside the new answer, and the weekly scorecard: untouched rate, fixes by reason, time to send. The Action posts the same report on the pull request and fails it on a regression.

WHAT THIS MEANS

Regressions are cases a human already approved

An approved answer that now comes back different is the only thing that should block a deploy, so the report lists those first, side by side with the baseline and the human's decision. Everything else — fixed, still wrong — comes after.

Nothing fired twice

Every tool call in a replay is answered from the recording, matched by fingerprint rather than position. A model that takes a different path still gets the right answers; a tool with side effects is refused. The receipt at the bottom of each report says exactly what was and wasn't tested.

Scored on the fields the human changed

An edit that touched priority is scored on priority, so rephrasing a structured answer isn't a regression. Free-text answers are scored by a judge model, and the report says which model judged.

The API

Five endpoints, and the SDKs call the same ones

Record runs, attach corrections, start replays, read the report.

API reference →

POST /v1/runsa recorded run: prompts, tool calls with their results, the final answer
POST /v1/correctionsapprove, edit, reject or escalate a run — it becomes a case with the fix attached
POST /v1/replaysreplay every case against a model and prompt version; pass several models for a matrix
GET /v1/replays/{id}the report: regressions first, then fixed and still-wrong, with the receipt of what was tested
POST /v1/tracesOTLP/HTTP — spans with gen_ai.* attributes become runs, no SDK required
Capabilities

What Overturn handles

Capture the fix, score the change, and block the pull request that breaks it.

Capture at the point of fix

No one opens another dashboard. The Zendesk app diffs the AI draft against what the expert sent and asks for one line on why; Slack, <CorrectButton> and /v1/capture cover everything else. The fix is recorded with the reason attached.

The scorecard

Untouched rate, fixes by reason, time to send, by team and by week. Never a per-person rate. The correction record and the regression suite come with it.

Safe replay

Tool calls are matched to recordings by fingerprint, so a model that takes a different path still gets the right answers. Nothing is emailed, refunded or written twice.

Can a cheaper model do the job?

Replay the same suite against several models at once and read them side by side: pass rate, regressions and cost per run, scored on your team's own corrections.

A corpus that is yours

Every correction exports as JSONL, so the record of how your team fixes its agent leaves with you. Pull the closest past fixes straight into your prompt with ov.examples().

Decision fields

Scoring looks at the fields the human changed, not the phrasing. A judge model handles free text, and says which model it used.

CorrectButton for your own UI

A React component and a one-line handler that turn the "fix this" button you already have into corrections, without changing your data model.

Deployment

Hosted, self-hosted, or air-gapped

Every deployment runs the same code. Self-hosting needs one Postgres with pgvector and the two containers; the SDKs only change a base URL.

Self-hosting guide →

Hostedapp.overturn.run. Sign in with email, create a key, send the first run. We run Postgres and the replay workers.
Self-hosteddocker compose up on any box with Postgres 16. Your recordings never leave your network; model calls go straight to the provider with your keys.
Air-gappedPoint the replay at a local model endpoint (any OpenAI-compatible server). No outbound traffic is required.

Already sending OpenTelemetry?

Point any OTLP/HTTP exporter at the endpoint below with your key in the authorization header. Spans with gen_ai.* attributes become model steps; tool spans with results become recordings. OpenLLMetry, Traceloop, the OpenAI and Anthropic instrumentations and LangSmith's export are verified.

FAQ

Frequently asked
questions

01Who is this for?⌄
Support and ops teams whose agents review AI-drafted replies before sending: customer support, claims, billing, field service, compliance review. If AI drafts into your Zendesk or Salesforce and nobody can say how often the draft was right, this is for you. Engineers get the same thing as an open-source SDK.
02What do I send?⌄
From Zendesk, nothing: the app captures the draft, the thread, what was sent and the reason. From code, runs: the input, every prompt and model answer, every tool call with its result, and the final output. OpenTelemetry users send the spans they already have.
03What comes back?⌄
A report per replay: regressions first (approved cases that now fail), then fixed cases, then still-wrong ones, each with the baseline, the new answer and the human's decision side by side, plus a receipt listing exactly which tool calls were answered from the recording.
04How is this different from Zendesk QA, Braintrust or LangSmith?⌄
Zendesk QA scores conversations after the fact, inside Zendesk, and now auto-scores Zendesk's own AI agents. Overturn is neutral: it captures the correction at the moment of send, whichever vendor drafted the reply and whichever help desk it lives in, and turns each fix into a test that runs before the next model or prompt change, not a score after it. Eval tools like Braintrust and LangSmith start from traces and need an engineer to write the test set; Overturn starts from the agent's fix. You can export the same cases as JSONL and keep using either.
05Does the model really learn how my experts decide?⌄
It reflects the decisions your experts already made: house rules, thresholds, wording, which cases get escalated. It does not learn underwriting. That is why the model and the suite ship together: nothing is promoted that fails the replay of your own experts' fixes, and it shadows production before it serves anything.
06What happens to tools with side effects?⌄
They're answered from the recording when the call matches a recorded fingerprint, and refused when it doesn't. Nothing is emailed, refunded or written during a replay. The receipt says which calls were refused so you can tell what wasn't tested.
07Which models and frameworks?⌄
Recording: OpenAI, Anthropic and the Vercel AI SDK in TypeScript; OpenAI and Anthropic in Python; anything that emits OpenTelemetry gen_ai spans. Replay: OpenAI, Anthropic, Google, OpenRouter, or any OpenAI-compatible endpoint, including local models.
08How much does it cost?⌄
Nothing during the open beta. Self-hosting is free forever under Apache-2.0. Replays call the model providers with your own keys, so you pay them directly — a 25-case replay on a small model costs a few cents.
09Where does my data live?⌄
Hosted: in one Postgres on Railway (US), encrypted at rest, raw runs purged after 30 days unless a case depends on them. Self-hosted: wherever you put it. Model calls during replay go straight from the replay worker to the provider.
